Atlas Billing stores account permissions in its application database. An incident disables a compromised service account. Restoring an earlier snapshot also restores that account’s enabled state.

Blackout retains the active requirement independently, then checks actual access and a legitimate invoice transaction.

What is real

  • SQLite snapshot and restore through the database backup API.
  • HTTP authentication and invoice creation against the restored application.
  • Source validation, evidence hashes and recorded request traces.
  • Optional live Gemini extraction, with an explicitly labelled offline baseline.

What is bounded

  • Two synthetic identities and one application.
  • The independent verifier and ledger are assumed trustworthy.
  • Session tokens are cleared on restore. Persistent-session attacks are outside this demo.
  • No malware scanning, insurer certification or claim of complete recovery safety.

Before returning to service

Incident responders can run this check between an isolated application restore and the decision to return it to service.

Blackout produces a reviewable record of which containment requirements held, which failed, and which remain unverified. External integrations are not implemented.
