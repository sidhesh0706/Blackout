Project Title:
Blackout: Containment Verification After Recovery

Briefly explain your idea:
Blackout verifies that restoring an application does not undo incident containment. The prototype targets account state stored in the restored application database, where an older backup can re-enable a compromised account even when normal health checks pass.

Our working prototype preserves source-linked security requirements outside the restored database and executes real HTTP checks to confirm that compromised access remains blocked while a legitimate user can complete a business transaction. It reports PASS, FAIL or UNVERIFIED, records evidence, and retests an operator-approved correction.

An optional AI adapter translates incident narratives into structured requirements. Independent validation checks approved source events, identity and subsequent changes before predefined tests execute. A clearly labelled rule-based mode runs without an API key; live AI evaluation remains future work.

The prototype demonstrates an actual SQLite restore, inspectable request traces, exportable evidence and eight repeatable challenge scenarios. All eleven integration tests passed, including a matrix of eight synthetic scenarios whose observed verdicts matched expectations. PASS applies only to the declared checks. Blackout supports responders evaluating a recovered application before returning it to service.
